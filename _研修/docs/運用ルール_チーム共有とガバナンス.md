# 運用ルール ― チーム共有とガバナンス

要約：WIKI.md を書き換えず、チームで共有するときに足す運用ルール。WIKIの「扱う情報のルール（一次URL＋日付）」を機械可読の境界へ拡張したもの。

## チーム共有の三点
個人Vaultをチームへ広げるときの要点は三つ … MindStudio「What Is the AI Second Brain」 https://www.mindstudio.ai/blog/what-is-ai-second-brain （2026-05-27）
- アクセス制御：全員が全部を引けるべきではない
- コンテンツガバナンス：誰が最新に保つか（[[OWNERS]] で割る）
- 取り込みワークフロー：新しい資料がどう確実に入るか

責任の割り当ては RACI 等の一般的なPM手法で整理してよい（特定の出典に依拠しない）。

## 書込みゲート
検証を通らないものは共有Vaultへ書き込まない。AI生成ノートは既定で certainty:仮説 とし、人手で確認したら last_verified を入れて昇格させる … Iwo Szapar「Company Second Brain with Agent Teams」 https://www.iwoszapar.com/p/company-second-brain-ai-agent-teams （2026-02-16、validation hook で検証通過前は書き込ませない）

## 作成主体の明示
human／AI／協働 を author で記録し、「誰がそう言ったか」の曖昧化を防ぐ … mem0「AI Agent Memory 2026」 https://mem0.ai/blog/state-of-ai-agent-memory-2026 （2026-04-01、actor-aware memory）

## 出所検証つき監査証跡
claim単位で一次URL＋日付へ辿れるようにし、log.md（追記のみ）で改ざんが分かる記録を残す。臨床AIの curated KB＋explicit provenance＋tamper-evident audit log が先進例 … Frontiers in AI https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1737532/full （2026-02-04、Alu & Oluwadare）
