# step03 ヒント：lint（整理）

## 参考プロンプト
~~~
lint
30_インプット/.raw/ のノートを整えてください。ファイル名は YYYY-MM-DD_カテゴリ_タイトル に統一、
frontmatter に tags と category と updated を付与、本文先頭に1行要約。
継続ナレッジは 00_ナレッジ、案件関連は 20_案件、取り込み元資料は 30_インプット へ。
複数カテゴリに関わるノートは、別カテゴリに索引（複製）も作って。最後に何をどう動かしたか一覧で。
~~~

## 仕組み
検索しやすさを優先し、重複を許容するのがこのVaultの方針です。1か所にきれいに片付けるより、複数の入口から辿れる方が後で探せます。

## 比較観点
- 別カテゴリの索引から、元ノートに辿り着けるか
- 命名規則がそろって、日付順・カテゴリ順で並べやすくなったか

## よくある勘違い
- 重複を嫌って1か所に寄せる → このVaultでは複製OK
- いきなり大量移動 → 対象一覧を出力させて、確認してから承認


## 発展課題の参考解
発展課題1「索引2カテゴリでの検索性比較」。
~~~
lint を使わず、次だけ手で試します。
00_ナレッジ と 20_案件 の両方に、この1ノートへの索引を作ってください。
索引には元ノートへのリンクと1行要約だけを置き、本文は元ノートに残す。
作り終えたら、両方の索引から元ノートに辿れるか確認してください。
~~~
期待される成果の形。同じノートへ2カテゴリから辿れます。索引に本文まで複製すると更新が二重になるので、リンクと1行要約に絞ると更新の手間が減ります。どちらの入口が探しやすかったかを memo.md に一言残せば、索引を増やす基準が自分の言葉で残ります。
