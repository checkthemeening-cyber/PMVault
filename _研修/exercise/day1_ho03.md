# Day1 HO03：lint で整える（自分で指示を書く）

## ねらい
溜まった `30_インプット/.raw/` のノートを、命名・日付・カテゴリ・リンクの規則に沿って整え、複数の入口から探せる状態を目指します。整理の指示を自分の言葉で書き、配布の `lint` が同じ意図のひな型だと確かめます。ここが Day1 の山場で、貯めた知識を後で使える形に変える回です。

## 使うもの
| 項目 | 内容 |
|---|---|
| 作業する場所 | Claude Code（ターミナル）で整理を指示、Obsidian で移動結果を確認 |
| 対象ファイル | `30_インプット/.raw/` のノート群 |
| 成果物 | 規則命名・frontmatter 付きのノート、別カテゴリの索引（複製）、予想メモ `_研修/memo.md` |
| 目安時間 | [25min] |

## 進め方
1. 考える：後で探せる・編集しやすい状態にするには、命名やカテゴリに何を入れるべきかを3つ予想し、`_研修/memo.md` の「## HO03」の見出しで書きます。
   - Tips：このVaultは重複を許容します。1か所にきれいに片付けるより、複数の入口から辿れる方を選びます。
2. 書く：`30_インプット/.raw/` を整える指示を自分の言葉で書きます。命名規則・frontmatter・振り分け・別カテゴリの索引（複製）まで含めます。配布の `lint` はまだ使いません。
   - 注意：いきなり大量移動させず、まず対象一覧を出力させてから承認します。
3. 実行：指示を実行し、提案された移動を確認してから進めます。継続ナレッジは `00_ナレッジ`、案件関連は `20_案件`、取り込み元資料は `30_インプット` が振り分けの目安です。
   - Tips：複数カテゴリに関わるノートは、別カテゴリに索引（複製）も作ると探しやすくなります。
4. 答え合わせ：`_研修/hints/step03_organize_hint.md` を開き、参考プロンプトと比較観点を確認します。配布の `lint` が同じ意図だと分かります。

## 自分で考えるポイント
- 別カテゴリの索引から、元ノートに辿り着けますか
- 命名規則がそろって、日付順・カテゴリ順で並べやすくなりましたか

## 達成チェック
- [ ] `30_インプット/.raw/` のノートが `YYYY-MM-DD_カテゴリ_タイトル` の規則で命名されている
- [ ] frontmatter に tags と category が付与されている
- [ ] 継続ナレッジ・案件関連・取り込み元が `00_ナレッジ` / `20_案件` / `30_インプット` に振り分けられている
- [ ] 別カテゴリに索引（複製）が作られ、そこから元ノートに辿れる

## うまくいかないとき
- 確認なしで大量に動いてしまう → 先に一覧を出させます。そのまま打てる例：
~~~
30_インプット/.raw/ を整える前に、何をどのカテゴリへ動かすかの一覧だけ先に出してください。私が承認してから実行してください。
~~~
- それでも直らないとき：ハンズオンHTMLの「詰まったときの即応」、`_研修/hints/step03_organize_hint.md`

## 発展課題（早く終わった方向け）
1. 索引2カテゴリでの検索性比較
   - 背景：どこに索引を置くと探しやすいかは、実際に作って比べると分かります。
   - 条件：元ノートは1つに保つ。索引（複製）だけを増やす。
   - 対象ファイル：`30_インプット/.raw/` から振り分けたノート、`00_ナレッジ` / `20_案件` / `30_インプット`
   - 実行すること：1つのノートに対し、別々の2カテゴリへ索引（複製）を作り、それぞれから元ノートに辿れるか試します。
   - 考える要素：索引が多いほど探しやすいのか、増やしすぎると何が起きるのか
   - ヒント：索引には元ノートへのリンクと1行要約だけを置き、本文は元ノートに寄せます。
   - 達成条件：同じノートへ2カテゴリから辿れ、どちらの入口が探しやすかったかを memo.md に一言残している
   - 参照：`_研修/hints/step03_organize_hint.md` の「発展課題の参考解」
