# 追加課題（早く終わった方向け・独立）

各HOの発展課題を終えた方向けの、HOの順番から切り離した課題です。答えは配りません。自分のテーマや判断で進めてください。作業フォルダはこのPMVault、記録は `40_運用/log.md` に残ります。

## 課題1：自分のテーマで第二の脳を1周
- 課題名：自分の業務テーマでの蓄積・整理・同期・実績化の一周
- 背景：テンプレをなぞるだけでなく、自分の実テーマで仕組みが回るかを確かめます。研修後にそのまま使い始められる状態を目指します。
- 条件：公開情報だけを扱う。機密・固有名詞の生データは入れない。HOで作ったテスト用ノートは残したまま、新しいテーマで作る。
- 対象ファイル：`00_Inbox/`（新規ノート）、`_templates/` のテンプレ、`_研修/_実績/INDEX.md`
- 実行すること：
  1. `/intake` か `/interview` で、そのテーマの知識を引き出してノートにする
  2. 命名・カテゴリ・リンクを整え、別カテゴリからも辿れるようにする
  3. 案件マスターを1枚作り、複製索引を `/sync-master` で同期する
  4. `/save-setup` で実績に残す
- 考える要素：自分のテーマだと、質問への答えやすさや整理の粒度がテスト題材とどう変わるか。
- ヒント：`/interview` は `/intake` より深く掘ります。答えにくい質問が来たら、そこが暗黙知の在りかです。
- 達成条件：新テーマのノートが整理され、Master→複製の同期が動き、`_研修/_実績/INDEX.md` に1行増えている。
- 参照：各工程は `_研修/hints/step02_intake_hint.md`、`_研修/hints/step03_organize_hint.md`、`_研修/hints/step04_sync_hint.md`、`_研修/hints/step06_savesetup_hint.md`。この課題自体の参考解は用意していません（自分のテーマで判断する課題です）。

## 課題2：Vaultの点検と直し
- 課題名：lint でのVault健全性チェックと修正
- 背景：ノートが増えると、孤立ノートやリンク切れ、カテゴリの抜けが出ます。増えた知識を探せる状態に保つ点検です。
- 条件：`/lint` の指摘をすべて直さず、直すものと残すものを自分で選ぶ。既存ノートの本文は必要な範囲だけ触る。
- 対象ファイル：Vault全体（`/lint` が対象を提示）、`index.md`
- 実行すること：`/lint` を実行し、孤立ノート・リンク切れ・4手がかりの欠落から2〜3件を選んで直す。直した理由をmemoに1行残す。
- 考える要素：機械的な指摘のうち、直す価値があるものと、あえて残してよいものの境目はどこか。
- ヒント：孤立ノートは、既存ノートからの関連リンクを1本足すだけで解消することが多いです。
- 達成条件：選んだ2〜3件が直り、`/lint` の再実行でその項目が消えている。
- 参照：この課題の参考解は用意していません。`/lint` の指摘文と、直した前後のノートを自分で見比べてください。

## 課題3：ask で過去の判断を引き出す
- 課題名：ask を使った蓄積知識の呼び出し確認
- 背景：貯めたノートが後から使えるかは、引き出せて初めて分かります。蓄積が検索に効いているかを確かめます。
- 条件：`/ask` には具体的な問いを投げる。返ってきた根拠ノートを必ず開いて確かめる。
- 対象ファイル：`20_案件/sessions/`、`30_インプット/sources/`、`00_Inbox/` などの既存ノート
- 実行すること：これまでに作ったノートに関する問いを1つ `/ask` に投げ、返答と、根拠として挙がったノートを照合する。
- 考える要素：`/ask` が拾えなかった知識があれば、それはどのノートの手がかり（命名・カテゴリ・リンク）が足りないからか。
- ヒント：要約でなく「時系列で」「論点だけ」と頼むと、`/ask` は構造化して返します。
- 達成条件：問いに対して根拠ノート付きの返答が得られ、拾えなかった知識があれば不足していた手がかりを1つ特定できている。
- 参照：この課題の参考解は用意していません。返答の根拠ノートを開いて内容と突き合わせてください。
