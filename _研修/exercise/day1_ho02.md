# Day1 HO02：intake / interview で引き出す

## ねらい
自分でノートを書き起こすのではなく、AI の質問に答えるだけで頭の中の知識がノートに落ちる流れを確かめます。`/intake` でテーマを1つ入れ、`/interview` で深掘りし、言語化できていなかった判断基準まで引き出せる状態を目指します。HO01 で整えた口調のまま、知識を貯める側の操作に入ります。

## 使うもの
| 項目 | 内容 |
|---|---|
| 作業する場所 | Claude Code（ターミナル）で `/intake` `/interview`、Obsidian でノートを確認 |
| 対象ファイル | 自分の頭の中（追っているテーマを1つ） |
| 成果物 | `30_インプット/sources/` や `00_ナレッジ/concepts/` に増えるノート、予想メモ `_研修/memo.md` |
| 目安時間 | [20min] |

## 進め方
1. 考える：今追っているテーマを1つ決めます。どう聞いてもらえれば楽に出せそうかを `_研修/memo.md` の「## HO02」の見出しで予想を書きます。
   - 注意：公開情報だけにします。機密は入れません。警告が出たら止めます。
2. 書く：ターミナルで `/intake` を呼び、決めたテーマを渡します。AskUserQuestion の問いに、選ぶ・短く答えるだけで進みます。
   - Tips：一度に多く聞かれて重いときは「1回の質問を答えやすい粒度で」と頼みます。
3. 実行：続けて `/interview` で同じテーマを掘ります。質問は事実→背景→判断→含みの順で深くなります。
   - Tips：出てきた固有名詞で公開情報の裏が取れるものは、URL を添えてもらうと後で確認できます。
4. 答え合わせ：`_研修/hints/step02_intake_hint.md` を開き、頼み方の例と比較観点を確認します。

## 自分で考えるポイント
- どう聞いてもらえれば、自分でゼロから書くより楽に出せますか
- interview のどの質問で、言語化できていなかった判断基準が出てきましたか

## 達成チェック
- [ ] `/intake` の AskUserQuestion に答え、`30_インプット/sources/` にノートが1つ以上保存されている
- [ ] `/interview` で同じテーマが事実→背景→判断→含みの順に深掘りされている
- [ ] 自分では書けていなかった判断基準が、ノートに1つ以上出ている
- [ ] ノートに公開情報以外が混ざっていない

## うまくいかないとき
- 質問が多すぎて答えるのがつらい → 粒度を下げてもらいます。そのまま打てる例：
~~~
1回の質問は選択式中心で、多くても1〜2問にしてください。答えがまとまったら 30_インプット/sources/ に1ノートで保存してください。
~~~
- それでも直らないとき：ハンズオンHTMLの「詰まったときの即応」、`_研修/hints/step02_intake_hint.md`

## 発展課題（早く終わった方向け）
1. 判断基準の domain への引き上げ
   - 背景：interview で出た判断基準は、次回以降の提案にも効く設定になり得ます。
   - 条件：`/interview` の結果だけを根拠にする。新しい機密は持ち込まない。
   - 対象ファイル：`30_インプット/sources/` のノート、`40_運用/domain.md`
   - 実行すること：interview で引き出した判断基準のうち、案件に効きそうなものを domain.md にメモします。
   - 考える要素：ノートに残す粒度と、domain に上げる粒度は何が違うか
   - ヒント：「テーマ固有の事実」はノート、「毎回の判断に効く基準」は domain と分けます。
   - 達成条件：domain.md の判断基準に、interview 由来の項目が1つ以上追記されている
   - 参照：`_研修/hints/step02_intake_hint.md` の「発展課題の参考解」
