# Day1 HO04：lint でノートの整合性を確認する

## ねらい
HO03で整えたノートに、孤立・リンク切れ・frontmatter 抜けが残っていないかを `lint` で点検します。整理したあとに機械的に確かめる習慣をつけ、Vault の健全性を維持する工程を体験します。

## 使うもの
| 項目 | 内容 |
|---|---|
| 作業する場所 | Claude Code（ターミナル）で指示。結果はObsidianでノートを開いて確認 |
| 対象ファイル | HO03で整えた `00_ナレッジ/` `20_案件/` `30_インプット/` 配下のノート |
| 成果物 | lint の点検レポート（孤立ノート・リンク切れ・frontmatter 不足の一覧）、`_研修/memo.md` の予想メモ |
| 目安時間 | [15min] |

## 進め方
1. 考える：整理したあとのノートに何が残りやすいか（孤立・リンク切れ・命名ゆらぎなど）を3つ予想し、`_研修/memo.md` にHO04の見出しで書きます。
2. 書く：`lint` を呼んで点検する指示をClaude Codeに書きます。どの範囲を点検するか、何を報告させるかを自分の言葉で伝えます。
   - Tips：「孤立ノート・リンク切れ・frontmatter 抜けを一覧で出して」と頼むと比較しやすくなります。
3. 実行：lint の結果を確認し、修正が必要なノートを1〜2件直してみます。Obsidianで修正後のノートを開いて変化を見ます。
   - 注意：lint は読んで報告するだけです。修正実行はClaudeに頼むか手動で行います。
4. 答え合わせ：`_研修/hints/step04_sync_hint.md` を開き、点検の観点と比較観点を確認します。

## 自分で考えるポイント
- lint の結果で、整理したつもりが抜けていたのはどこですか
- 孤立ノートとリンク切れは、それぞれ何が原因になりやすいですか

## 達成チェック
- [ ] `lint` を実行し、孤立ノート・リンク切れ・frontmatter 不足の一覧が出ている
- [ ] 一覧のうち1件以上を修正している
- [ ] 修正後にもう一度 lint を実行し、指摘数が減っていることを確認している

## うまくいかないとき
- lint が長い一覧を出しすぎる → 「孤立ノートだけに絞って」と範囲を絞ります。そのまま打てる例：
~~~
lint で 30_インプット/ 配下のノートだけ点検してください。孤立ノートとリンク切れを一覧で出し、
修正が必要な件数を報告してください。修正は私が確認してから実行します。
~~~
- それでも直らないとき：ハンズオンHTMLの「詰まったときの即応」、`_研修/hints/step04_sync_hint.md`

## 発展課題（早く終わった方向け）
1. 修正前後の比較
   - 背景：lint を2回実行することで、整理の前後で何が変わったかを数値で確かめます。
   - 条件：HO03で整えたノートをそのまま使う。新しいノートは作らない。
   - 対象ファイル：HO03で振り分けたノート全体
   - 実行すること：lint の結果を1回目のまま `_研修/memo.md` に貼り、1件修正してから2回目の lint を実行。件数の変化を記録します。
   - 考える要素：孤立ノートを減らすには何をすれば効くか
   - ヒント：リンクを1本足すだけで孤立が解消することがほとんどです。
   - 達成条件：lint の指摘件数が1件以上減り、その差分を memo.md に記録している
   - 参照：`_研修/hints/step04_sync_hint.md` の「発展課題の参考解」
