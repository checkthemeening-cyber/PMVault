# Day1 HO01：環境の起動と persona / domain の記述

## ねらい
Claude Code を起動したとき、AI が最初にどのファイルを読んで動くのかを確かめます。そのうえで persona.md を自分好みの口調に、domain.md を自分の役割に書き換え、次の応答から反映される状態を目指します。Day1 は Vault 側で設定を整える回で、その最初の一歩がこの演習です。

## 使うもの
| 項目 | 内容 |
|---|---|
| 作業する場所 | Claude Code（ターミナル）で指示、Obsidian で変更結果を確認 |
| 対象ファイル | `40_運用/persona.md`、`40_運用/domain.md` |
| 成果物 | 書き換わった `40_運用/persona.md` / `40_運用/domain.md`（PMVault 直下）、予想メモ `_研修/memo.md` |
| 目安時間 | [15min] |

## 進め方
1. 考える：どう指示すれば口調が変わるか、具体的に何を書けば伝わるかを3つ予想し、`_研修/memo.md` の「## HO01」の見出しで書きます。
   - Tips：「丁寧に」だけでは伝わりません。避けたい言い回しの例まで挙げると反映されやすくなります。
2. 書く：ターミナルで `cd ~/Documents/PMVault` の後 `claude` を起動します。まず「このVaultの構成と、起動時に読むファイル、使えるSkillを教えて」と聞きます。
   - 注意：ノートが見つからないと返るときは起動フォルダ違いです。`cd ~/Documents/PMVault` からやり直します。
3. 実行：persona.md を自分の言葉に書き換える指示を出します。続けて domain.md の役職・担当領域・判断基準を、AI の質問に答えながら埋めます。配布の `/tune-persona` はここでは使いません。
   - Tips：domain の空欄は空のままで構いません。使いながら後で足せます。
4. 答え合わせ：`_研修/hints/step01_persona_hint.md` を開き、参考の書き方と `/tune-persona` の使いどころを確認します。

## 自分で考えるポイント
- 口調を変えるには、指示に何を書けば AI に伝わりますか
- domain.md の判断基準は、後の提案のどこに効いてきそうですか

## 達成チェック
- [ ] `cd ~/Documents/PMVault` → `claude` で起動し、起動時に CLAUDE.md と persona.md / domain.md を読むと確認できている
- [ ] `40_運用/persona.md` が自分の言葉に書き換わっている
- [ ] 書き換え後の応答の口調が、指定どおりに変わっている
- [ ] `40_運用/domain.md` の役職・担当領域・判断基準のいくつかが埋まっている

## うまくいかないとき
- 口調が変わらない → 避けたい言い回しの具体例まで指示に足します。そのまま打てる例：
~~~
40_運用/persona.md を、前置きと謝罪を省いた簡潔なですます調に書き換えてください。「〜させていただきます」は使わない。反対意見ははっきり言う。書き換えたら、その口調で一度自己紹介してください。
~~~
- それでも直らないとき：ハンズオンHTMLの「詰まったときの即応」、`_研修/hints/step01_persona_hint.md`

## 発展課題（早く終わった方向け）
1. tune-persona での作り込み
   - 背景：手で書くより、質問に答える形の方が抜けなく詰められます。
   - 条件：`/tune-persona` を使う。domain.md は変更しない。
   - 対象ファイル：`40_運用/persona.md`
   - 実行すること：`/tune-persona` を呼び、質問に答えながら口調と、触れてほしくない話題まで書き込みます。
   - 考える要素：手書きの書き換えと、質問形式とで、出来上がりに差が出るのはどこか
   - ヒント：好みだけでなく「避けたいこと」を1問ぶんは必ず答えます。
   - 達成条件：触れてほしくない話題が persona.md に1つ以上記録され、その話題を振ったとき応答が控えめになる
   - 参照：`_研修/hints/step01_persona_hint.md` の「発展課題の参考解」
