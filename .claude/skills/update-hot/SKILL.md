# update-hot ― ホットキャッシュを更新 + log.mdの棚卸し

## やること
1. 直近の会話・作業から「いま取り組んでいること」「直近で分かったこと」を~500語にまとめる
2. `40_運用/hot.md` を上書き更新する（古い文脈は残さず、最新だけを置く）
3. 次のセッションで、まずここを読めば続きから始められる状態にする
4. log.md の棚卸し（下記）を行う

## log.mdの棚卸し（知識への昇格）
log.md は追記のみの生ログで、readabilityより網羅性を優先している。放置すると「後で見返しても何が重要だったか分からない記録の山」になるため、update-hot のたびに次を行う。

1. `40_運用/log-digest-checkpoint.md` を読み、「最終処理日」を確認する（ファイルが無い、または未記入なら log.md の最初のエントリから対象にする）
2. log.md のうち、最終処理日より新しい日付見出し（`## YYYY-MM-DD`）のエントリだけを対象にする
3. 各エントリを次の基準で判定する
   - 昇格する：方針転換・規約変更・手法や進め方の決定・繰り返し参照されそうな汎用的な知見
   - 昇格しない：定型Hookの実行記録、実装の逐一的な修正ログ、単なる進捗報告（ただし設計判断を伴うものは概念化の余地あり）
4. 昇格するものは [[00_ナレッジ/concepts/プロパティ統制語彙]] に従い、次のどちらかとして新規ノートを作る
   - 意思決定 → `20_案件/decisions/` に `_templates/意思決定ログ_テンプレ` から1決定1ノートで作成
   - 汎用的な概念・手法 → `00_ナレッジ/concepts/` に概念ノートとして作成
   いずれも4つの手がかり（type/when/topic/status）と命名規則 `YYYY-MM-DD-種類-主題.md` を守る
5. `index.md` のカタログに新規ノートを追記する
6. log.md 自体は書き換えず、末尾に新しいエントリとして「どのログをどのノートへ昇格したか」を追記する（例：`## 2026-07-25（棚卸し）` の下に「07-16の意思決定エントリを 20_案件/decisions/2026-07-16-意思決定-〇〇.md へ昇格」のような1行）
7. `40_運用/log-digest-checkpoint.md` の最終処理日を今日の日付に更新する
8. 昇格対象が無ければ、ノートは作らずチェックポイントの日付だけ更新して終える

## 注意
- 長く書きすぎない（hot.md は~500語）。トークン節約が目的
- 確定した知識は wiki ページ側に、流動的な作業文脈だけ `40_運用/hot.md` に
- log.md の過去エントリは編集・削除しない。棚卸しは「新しいノートを作って追記する」だけで完結させる
- `40_運用/log-digest-checkpoint.md` は状態を持つだけの小さな運用ファイル。index.md には載せない（hot.md/log.mdと同じ扱い）
