# 共有の第二の脳

要約：複数人とAIで一つのVaultを運用するとき、問題になりやすいのが、古い情報を確度の表示なしに返して品質が無警告で落ちること。出所・確からしさ・鮮度・更新責任をfrontmatterの信頼レイヤーで持ち、引くときに足切りできる形にする。このノート自身が信頼レイヤーの記入例を兼ねる。

## なぜ信頼を本文でなくfrontmatterに持つか
- 意味的類似度には時間軸がない。陳腐化した埋め込みも新鮮なものと同じ高スコアで引かれ、回答品質が無警告で落ちる … Tian Pan「The RAG Freshness Problem」 https://tianpan.co/blog/2026-04-10-rag-freshness-problem-stale-embeddings-silent-failure （2026-04-10）
- 古い知識ベースは構造が正しく断定口調なので、誤りが通常の監視に映らない。鮮度は明示メタデータで持つ … 同上

## 信頼レイヤー（claim系ノートに任意で足す）
| 項目 | 何を書くか |
|---|---|
| certainty | 確実 / 有力 / 仮説 / 未確認 |
| source | 一次URL / 内部資料名 / AI生成 |
| author | human / AI / 協働 |
| last_verified | 最終の人手確認日 |
| review_by | 次回見直し期日 |
| owner | 更新責任者（[[OWNERS]]と対応） |

既存の type/status/date/topic/tags は全ノート必須のまま変えない。信頼レイヤーは主張・意思決定・取り込み資料・AI生成ノートにだけ足す。雑メモには付けない（増やしすぎない原則）。記入仕様と陳腐化しきい値の詳細は [[出所と確からしさ_テンプレ]]。

## 人間とAIの役割分担
- AI生成ノートは既定で certainty:仮説。人手で確認したら last_verified を入れて 有力／確実 へ昇格させる … mem0「AI Agent Memory 2026」 https://mem0.ai/blog/state-of-ai-agent-memory-2026 （2026-04-01、actor-aware memoryが「誰がそう言ったか」の取り違えを解く）
- 誰が書いた／推論したかを author（human/AI/協働）で残し、人間発言とAI推論を分ける

## チームで共有するとき（curator + contributor）
- 各自はprivate brainを手元に持ち、選んだドメインの構造化要約だけを共有する。生のbrainは外に出さない … Tali Rezun「The Shared Brain」 https://medium.com/@talirezun/the-shared-brain-when-second-brains-start-thinking-together-0d2ad54413d9 （2026-05-19、"Private brains remain private. Shared intelligence is built only from explicit contributions."）
- curatorが矛盾解消・リンク修復・attribution保持で集合wikiを再構築し、参加者はread-onlyで取り込む … 同上
- 複数の人やエージェントが同じページを同時に書くときは、ページ単位のadvisory lock（取得／解放、60秒で自動解放）で破損を防ぐ … claude-obsidian https://github.com/AgriciDaniel/claude-obsidian

## チームで共有するときの適用
一次情報URL＋日付を明記する規約に沿わせ、検証を通した要約だけをチームで共有する。書込みゲートで検証を通らないものは共有Vaultに入れない。運用の詳細は [[運用ルール_チーム共有とガバナンス]]。
