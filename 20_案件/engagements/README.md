# engagements ― 案件ワークスペース

このVaultでコンサルの仕事を束ねる最上位フォルダです。提案も議事録も事例も数字も、最後は案件にぶら下がります。その親をここに置くと、横断検索の基点になります。

## 何を置くか
1案件1フォルダ。`20_案件/engagements/<案件名>/` を切り、直下に案件プロファイルを置きます。

- `20_案件/engagements/<案件名>/案件プロファイル.md` … 初日に開く1枚。[[_templates/案件プロファイル_テンプレ]] から作る
- `20_案件/engagements/<案件名>/論点と前提.md` … 案件期間中ずっと更新する論点・仮説・前提の記録（[[20_案件/decisions/README]] 参照）
- `20_案件/engagements/<案件名>/ステークホルダーマップ.md` … 意思決定者と影響力（[[_templates/ステークホルダーマップ_テンプレ]] から作る）

議事録・インタビュー・意思決定ログは命名 `YYYY-MM-DD-種類-主題.md` で同じフォルダに置き、frontmatter の topic を案件名に揃えます。これで「この案件で、いつ何を決めたか」を時系列に引けます。

## 4手がかりの乗せ方
- type は案件プロファイルだけ `案件`。配下のノートはそれぞれの種類（会議録・意思決定・インタビュー）
- topic は全ノート共通で案件名。これが束ねの軸
- status は案件全体の状態を案件プロファイルに（進行中 / 完了 / 保留）

## 新規案件の立ち上げ
1. `20_案件/engagements/<案件名>/` を作る
2. [[_templates/案件プロファイル_テンプレ]] をコピーして埋める
3. index.md の『案件（20_案件/engagements/）』に案件名を1行追加
4. 関わる人は 20_案件/entities/ に人物ページを作り、ステークホルダーマップから [[ ]] で参照（人物の詳細は 20_案件/entities/ 側に置き、マップでは役割と温度感だけ持つ）

## なぜフォルダで切るか
案件は締切のある動くプロジェクトで、終わればアーカイブします。書き物プロジェクトはフォルダ、知識はリンク中心という整理に沿った使い分けです（[[00_ナレッジ/concepts/PKM手法カタログ]] の PARA・フォルダ vs リンク の項）。終了案件は Vault の検索対象から外れやすいため、要点だけ [[00_ナレッジ/concepts/]] に概念として残すか、MOC を1枚作って辿れるようにします。
